# 微信登录接入说明（H5）

> 结论先说：**入口只有一个 —— 用微信扫码打开 H5。**
> 页面在任何浏览器都能打开、可匿名浏览；**只有微信内才能登录**；需要登录的地方自动请求微信授权，
> 用户点「允许」即自动登录并回到刚才的页面。没有账号密码、没有短信验证码，也不做微信外的登录。

本文分两部分：
- **A. H5 侧已实现的内容**（本次交付，可直接跑）
- **B. 其它地方要做什么**（微信资质、后端接口、部署运维）——H5 仓范围之外，但缺一件就跑不起来

---

## A. H5 侧实现

### A1. 用户看到的流程

```
运营物料/物料牌上的二维码
        │  扫码（微信内打开，或普通浏览器打开）
        ▼
   H5 任意页面（首页 / 场地 / 咨询 / 订单…）        ← 未登录也能浏览
        │
        │  点到「需要登录」的动作：立即预约、提交咨询、我的、订单…
        ▼
   ┌─ 微信内 ────────────────┐   ┌─ 微信外 ─────────────────────┐
   │ 自动发起微信网页授权      │   │ 不跳授权，提示「请用微信扫码打开」 │
   │ 微信弹出授权页（用户点允许）│   │ 可复制当前链接到微信里打开        │
   └──────────┬──────────────┘   └──────────────────────────────┘
              │ 允许
              ▼
   微信回跳 H5（?code=&state=）
              │
              ▼
   H5 把 code 交后端换 token → 自动登录 → 回跳原页面继续操作
```

要点：
- **登录时机是「需要登录时」**，不是一进来就弹授权。匿名浏览不受影响。
- **「用户同意」就是微信授权页那一次点「允许」**，符合平台合规要求。
- **不会出现「页面一加载就跳授权」**：微信会把无用户交互的自动跳转固化成快照页（只显示「点击访问完整网页」）。
  因此页面加载兜底（比如深链直接进预约页）会先弹一次确认框，用户点「微信登录」后才跳授权。
- 拒绝授权：提示「可随时重新登录」并返回，不写任何登录态。

### A2. 代码位置

| 文件 | 职责 |
| --- | --- |
| `src/utils/wechat.ts` | 纯函数：微信环境判断、授权链接拼装、state 生成、回跳参数解析/清理。不碰 store 与请求 |
| `src/services/auth.ts` | 登录编排唯一入口：`beginLogin` / `requireLogin` / `completeMockLogin` / `resumeFromCallback` / `initAuth` / `logout` |
| `src/config/env.ts` | 微信相关配置唯一出口（业务代码不直接读 `import.meta.env`） |
| `src/pages/login/login.vue` | 三种角色：微信内 real=一键授权；微信内 mock=模拟授权；微信外=扫码引导 |
| `src/App.vue` | `onLaunch` 调 `initAuth()`：恢复登录态 + 处理微信回跳 `?code=&state=` |
| `src/utils/request.ts` | 401 统一清登录态并带去登录页（不做编排，避免循环依赖） |
| `src/mock/router.ts` | Mock 的 `/auth/wechat-login`（模拟 code2session + 建档）、`/auth/me`、`/auth/logout` |

登录门调用方式（页面统一用它，不要自己写跳登录页）：

```ts
import { requireLogin } from '@/services/auth'

// 用户点击触发：微信内直接跳授权（合规，因为有用户交互）
if (!requireLogin('/pages/apply/venue')) return

// 页面 onLoad 兜底（无用户交互）：先弹确认再跳，避免微信快照页
requireLogin('/pages/apply/venue', { fromClick: false })
```

### A3. 配置项

`src/config/env.ts` 读取，值放在 `.env` 分层里：

| 变量 | 说明 | 默认 |
| --- | --- | --- |
| `VITE_WX_AUTH_MODE` | `mock`（本地模拟授权）/ `real`（真实微信授权） | `.env` 里是 `mock`，`.env.production` 里是 `real` |
| `VITE_WX_APP_ID` | 服务号 AppID（公开标识，**不是密钥**，可入库） | 空 |
| `VITE_WX_SCOPE` | `snsapi_userinfo`（弹授权页、可拿昵称头像）/ `snsapi_base`（静默只拿 openid） | `snsapi_userinfo` |
| `VITE_WX_REDIRECT_URI` | 授权回调基址，必须在公众平台「网页授权域名」下；空则取站点根目录 | 空 |

**AppSecret 绝对不能进前端**（不带 `VITE_` 前缀也会被构建进产物，所以根本不要放），只能在后端环境变量里。

降级规则：`real` 模式但 `VITE_WX_APP_ID` 为空时，前端自动降级为 `mock` 并 `console.warn` —— 避免跳到必然报错的授权链接。

### A4. 两种模式怎么用

- **mock（默认，开发/演示/自动化）**：不需要任何微信资质。登录页展示模拟授权层，点「允许」即登录（写本地 token）。
  用于本地演示和 e2e 回归；`node .shots-tmp/h5-login-e2e.mjs` 覆盖 15 个断言。
- **real**：真实跳转微信授权页。需要 A3 里的 AppID + 公众平台网页授权域名。
  `node .shots-tmp/h5-login-real-e2e.mjs` 在不连真实微信的前提下校验了协议链路（授权 URL 参数顺序/编码、
  state 校验、伪造 state 拒绝、回跳换 token、回跳目标页、微信外引导），21 个断言。

### A5. 关键实现细节（改动前务必知道）

1. **授权链接参数顺序不能改**：`appid → redirect_uri → response_type → scope → state → #wechat_redirect`，
   微信对链接做正则强匹配校验，顺序错了授权页直接打不开。
2. **`state` 只放随机串**（`[a-zA-Z0-9]`，24 位）。官方限制 state ≤128 字节且只能用字母数字，
   所以「登录后回哪一页」不能塞进 state，单独存 `sessionStorage`，回跳时用 state 校验来源再取回目标。
3. **`redirect_uri` 用站点根目录**（`location.origin + 目录/`），不带 hash。
   这样微信把 `?code=&state=` 拼在 `?` 后，解析没有歧义；应用内路由靠 `uni.reLaunch` 回跳。
4. **`code` 一次性、5 分钟过期**：回跳时先清地址栏再换 token，避免刷新/分享导致二次使用。
5. **换 token 必须走后端**：前端拿 code 调 `POST /api/auth/wechat-login`，AppSecret 只在服务端。
6. **401 处理**：`request.ts` 清 storage + 内存登录态，跳登录页（登录页自己再按环境决定是跳授权还是提示扫码），
   且已在登录页时不再重复跳转，避免死循环。

## B. 其它地方要做什么（H5 仓之外）

### B1. 微信资质（不能跳过）

| 场景 | 要求 | 费用/周期 |
| --- | --- | --- |
| **本地/开发调试** | 微信公众平台**测试号**（`https://mp.weixin.qq.com/debug/cgi-bin/sandbox?t=sandbox/login` 微信扫码登录即得 AppID/AppSecret），在「网页服务-网页帐号-网页授权获取用户基本信息」里配置授权回调域名 | 免费、几分钟 |
| **正式上线** | **已认证的服务号**（企业/组织主体）+ 微信认证；个人订阅号不行，未认证服务号也不行 | 认证 300 元/年，审核 1–5 个工作日 |
| 域名 | 公众平台「设置与开发-账号设置-功能设置-网页授权域名」填写**全域名**（不带 `http://`），该域名下所有页面都能授权；微信要求回调建议用 **HTTPS** | 域名需已完成 ICP 备案（国内） |

要点：
- 网页授权是**服务号能力**；订阅号、未认证服务号、小程序、开放平台网站应用都不是这套流程
  （开放平台「网站应用扫码登录」是另一件事：电脑上显示二维码、手机扫码确认，本次没有做）。
- 授权域名只认**全域名**：配了 `h5.example.com` 就只有它能授权，`pay.h5.example.com`、`example.com` 都不行。

### B2. 后端接口（`drone-dispatch-server`，需后端同学实现）

H5 只认一个契约：

```
POST /api/auth/wechat-login          （匿名可访问，加入 JwtAuthInterceptor 白名单）
body: { "code": "<微信回跳的 code>" }

成功: { "code": 0, "data": { "token": "<JWT>", "user": { "id", "nickname", "avatar", "phone" } } }
失败: 非 0 code + msg（前端会 toast 提示并可重试）
```

服务端要做的事：

1. **code2session**：`GET https://api.weixin.qq.com/sns/oauth2/access_token?appid=&secret=&code=&grant_type=authorization_code`
   → 拿 `openid` / `access_token` / `unionid`。
2. **快照页账号必须拒绝**：返回里 `is_snapshotuser == 1` 表示是微信快照页虚拟账号，不能当真实用户登录。
3. **拉资料**：`GET https://api.weixin.qq.com/sns/userinfo?access_token=&openid=&lang=zh_CN` → `nickname` / `headimgurl`。
4. **建档**：`users` 表加 `openid`（唯一索引）、`unionid`（可空）、`avatar`、`nickname`；
   同一 openid 复用账号，首次登录自动建档。
5. **签发 JWT**：与现有管理端 token 区分角色（如 `role=USER`），`JwtAuthInterceptor` 按接口放行 ADMIN / USER。
6. **配置**：`app.wx.app-id`（可入库）、`app.wx.app-secret`（**只**放环境变量 `WX_APP_SECRET`）。
7. **CORS**：`app.cors.allowed-origins` 现在只放了 5173，H5 实际跑 5174，联调前要加。
8. **安全**：登录限流（可复用现有「账号+IP」窗口）、日志里 openid 脱敏、code 只消费一次。
9. **授权撤销事件**（上线后建议）：订阅 `user_authorization_revoke` 消息推送，用户撤回昵称头像授权时清理本地缓存资料。

### B3. 部署与联调

1. H5 部署到**已配置网页授权域名的 HTTPS 地址**（生产）。
2. 本地真机联调：微信必须能访问到回调地址 → 用内网穿透（cpolar / natapp / ngrok）把 `5174` 暴露成 HTTPS 域名，
   把这个域名填进测试号的授权回调域名，再把 `VITE_WX_REDIRECT_URI` 指向它。
3. 二维码：运营物料上的二维码指向 H5 URL 即可（可带来源参数）。**H5 不负责生成二维码**。
4. 用户协议 / 隐私政策：登录页已有入口占位，需补真实页面（合规要求，且微信审核会看）。

### B4. 可选：微信小程序端

工程里 `manifest.json` 已预留 `mp-weixin`。小程序不能走网页授权，要走：
`uni.login()` 拿 code → 后端 `jscode2session` 换 openid → 同样的 `{ token, user }` 契约。
H5 这轮的登录编排（`services/auth.ts`）已经按「登录流程集中一处」组织，小程序端接同一个服务层即可，
但**这轮没有实现也没有验证**。

## C. 排错对照表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 授权页提示「该链接无法访问」/ 10003 | `redirect_uri` 与公众平台配置的授权域名不一致 | 检查域名（全域名匹配）、协议、端口 |
| 10005 | 账号没有 `snsapi_userinfo` 权限 | 用已认证服务号或测试号 |
| 10006 | 测试号要求先关注 | 关注测试号 / 配置体验者 |
| 10012 / 10011 | appid / redirect_uri 为空 | 检查 `.env` 与授权链接 |
| 微信里显示「点击访问完整网页」 | 页面加载后无交互直接跳授权 | 已处理：页面加载兜底改为先弹确认（`fromClick: false`） |
| 登录后没回到原页面 | `redirect` 丢失 / 被清 | 检查 `sessionStorage` 的 `wx_oauth_redirect` 与 `beginLogin` 传参 |
| 一直循环跳登录页 | 401 反复触发 | 已处理：登录页不再重复跳转；后端需把 `/auth/wechat-login` 加白名单 |
| 普通浏览器打开点登录没反应 | 预期行为（只支持微信内） | 显示「请用微信扫码打开」+ 复制链接 |
